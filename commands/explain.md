---
description: Explain a UI style: what it is, the technique, when to use it, and what it costs
argument-hint: [style, e.g. glassmorphism]
---

Use the `ui-design` skill. Explain: `$ARGUMENTS`.

Load the matching reference from the skill's map. If the request names no style but describes a look ("that frosted panel thing", "the one with the thick black borders"), identify it first, then explain.

1. **Open with what it is in one sentence**, then the technique with real values: the CSS, the shadow recipe, the material name. A style explained without its numbers is a mood board.
2. **Name when it works and when it does not**, tied to product and audience rather than taste.
3. **State the cost**: contrast, legibility, performance, build effort, or distinctiveness. Every style has one.
4. **Give the accessibility floor for this style specifically** — the setting it must honour, the ratio it usually fails, the fallback it needs.

If the user's own product is in scope, ask with `AskUserQuestion` whether they want the recommendation for their case rather than the general explanation, and answer that instead.
